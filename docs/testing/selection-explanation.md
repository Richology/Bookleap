# 划线解释验证

入口：工作台打开任意已完成的精华卡片，选择 1–800 字，点击「解释一下」。总览卡片是打开阅读器的入口；解释在阅读器当前卡片内展开，不持久保存。选区菜单统一提供解释和书摘图；已有高亮的悬停菜单提供解释、书摘图与删除高亮，直接解释原高亮内容，无需重新选择。

## 自动回归

```sh
node --test lib/bookAnalysis/*.test.mjs lib/prompts/promptContracts.test.mjs lib/skills/markdownCleanup.test.mjs
npm run lint
npx tsc --noEmit
```

浏览器回归复用可选 `local-mcp` 开发依赖中的 `playwright-core`，需先安装该子项目依赖，并启动网页开发服务器。默认本地端口 3001，可覆盖地址与 Chrome 路径：

```sh
BOOKLEAP_TEST_URL=http://127.0.0.1:3001 node scripts/selection-explanation-browser.mjs
```

脚本使用独立浏览器上下文与体验书，不访问用户的浏览器书库；模型接口使用受控响应，覆盖桌面、390px 触屏模拟、加载、请求失败、重试保留选区、无可靠原文、例子标签、原文显示、收起与超长选区，以及生成书摘后从高亮悬停菜单直接解释。原文是否可引用由领域测试验证：真实连续原文通过，改写、未知编号和伪造位置不通过。

## 数据和限制

复用当前书籍的 `analysisContext.samples`，有 `text` 时使用原文抽样，否则使用保存的 `preview`。历史记录目前通常仅保留每个抽样的前 260 字，因此可能找不到支持解释的原文，界面应如实提示。摘要和模型生成的 CardEvidence 不作为逐字引用真源。按选区关键词排序最多 8 个抽样，每个最多 6000 字；这一召回方式不保证语义匹配全面。

模型只返回解释、可选例子及引用建议。服务端核验引文是否为原文抽样的连续子串，章节名取自同一抽样，忽略模型提供的位置；不生成页码或原文跳转。

当前自动测试不验证真实模型的解释质量，也不能代替 iOS Safari / Android Chrome 的系统长按选择菜单测试。真机需确认长按、拖动选择手柄、底部操作、滚动及收起回到原位置，并确认原有高亮和书摘仍可使用。上线前用配置好的模型抽查一个有原文上下文的书籍与一个无原文的旧记录。
