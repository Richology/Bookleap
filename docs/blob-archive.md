# Blob 临时中转与本地原书归档

生产上传继续使用 Vercel Blob 客户端直传（超过 5 MB multipart），单本上限仍是 50 MB。该任务不改变章节解析、AI 分析或浏览器书库保存方式。

## 安全窗口

- 解析开始前读取 Blob 元数据，只接受上传不足 23 小时的同库对象；过期则提示重新上传。
- 生产解析函数最大运行 300 秒。归档只处理上传满 24 小时的对象，留出至少一小时隔离窗口。
- 归档每 24 小时运行一次，所以原件通常会在上传 24–48 小时后归档并清理。运行时新上传及尚在解析窗口的文件会保留。
- 清理前检查线上 `GET /api/upload` 的策略版本。未发布配套解析规则时拒绝自动删除。

## 目录及凭据

项目根目录 `book-archive/` 仅在运营者电脑保存，已加入 `.gitignore` 和 `.vercelignore`。不要通过强制 git add 提交该目录。

`book-archive/.env` 配置 `BLOB_READ_WRITE_TOKEN`，仅本机使用，权限应为 600。运行需要 Node.js 22.6+（使用内置 parseEnv）及项目依赖。

每个对象保存为 `files/<对象版本哈希>/original.<格式>` 和 `receipt.json`。清单保留原路径、上传时间、大小、ETag、SHA-256 和归档/删除时间；旧的随机文件名仍可通过清单对应。书名不明时不会猜测或错误重命名。`last-inventory.json` 保存最近云端清单，`last-run.json` 保存运行摘要。

## 执行

在项目根目录运行：

```sh
node scripts/archive-blobs.mjs --dry-run  # 只列举，不下载/删除
node scripts/archive-blobs.mjs            # 只备份，不删除
node scripts/archive-blobs.mjs --delete   # 完整验证后清理已备份对象
node --test scripts/archive-blobs.test.mjs
```

Codex 自动化每 24 小时在原项目目录执行最后一种归档模式。电脑和 Codex 必须能够运行；本机离线时云端不会自行删除。不要在临时 worktree 中运行归档。

## 完整性与重试

下载先写临时文件，校验 ETag、字节数和落盘 SHA-256，fsync 并原子重命名，再保存归档凭证。删除前重新核对云端对象，并用 `ifMatch` 条件删除，防止删掉后来替换的版本。失败保留云端对象，下次重试；已有副本也会重验哈希，不把文件存在视为成功备份。

一次只允许一个实例运行。若进程被强制终止，`.run-lock` 会保留；先检查其中 `owner.json` 的 PID，确认没有归档进程运行，才手动移除锁目录并重试。不要自动绕过锁。

401/403/429、网络错误、磁盘不足或校验失败应排查并重试，不能改用无条件删除。Blob 因额度被封锁时可能能列举/删除，却不能下载；自动化不得删除未备份文件。历史原件的单独清理需要明确授权，不能把历史豁免变成定时任务规则。

本地单份原件不等于灾难备份；该目录应随电脑现有备份策略保护。不要删除 Blob 存储库或解除项目连接，大文件直传仍依赖它。
