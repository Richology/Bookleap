# 书跃「本地 MCP」Spec

日期：2026-11-08。状态：用户已确认产品共识，授权在本项目另开任务实施；技术路线须通过下述验证，尚未实现。本文是本功能实施与验收依据。

## 1. 目标与范围

让用户首次安装、配对一次后，书跃网页新增的拆书内容自动进入自己的电脑知识库；浏览器关闭时，Codex 仍能通过本地 MCP 检索、读取、引用最后成功同步的内容。综合分类、跨书比较、洞察由调用方 Agent 完成。

- 不新增书跃注册登录、云数据库或云端书库同步。
- 首版 Agent 接入重点为 Codex，MCP 协议接口保持标准化；不宣称所有客户端已验证。
- 平台目标：macOS Apple Silicon、macOS Intel、Windows x64；Windows ARM 暂不承诺。
- Safari、Chrome 为重点，兼顾 Edge、Firefox 桌面版；Safari 指 macOS，不要求 Windows Safari 或移动浏览器。
- MCP 工具只读，不修改/删除阅读记录、不将对话写回、不重新拆书或生成海报。
- 检索无需额外 API Key、模型下载或向量服务。分类不凭空成为既有元数据，可由 Codex 分页读取并推断，须注明推断。
- 本地检索可离线；Codex 使用云模型时，返回的内容可能进入模型上下文，首次授权须说明。

## 2. 已核实的代码事实

- `lib/workspaceStorage.ts`：IndexedDB `bookleap_workspace_v1` 的 `historyRecords`，有旧 localStorage 迁移与兜底。
- `app/workspace/page.tsx` 的 `HistoryRecord`：保存书名、作者、格式、六类分析、可选 `analysisContext` / `cardEvidence` 等，不是完整电子书存档。
- `lib/bookAnalysis/context.mjs` 持久化的是裁剪片段；旧记录可能缺少证据，存储降级也可能去除上下文。
- 阅读反思、高亮、训练记录分散在 localStorage；`lib/highlights.ts` 的高亮定位主要属于分析卡片，不可冒充原书页码。
- 现有 JSON 备份有 v1/v2；可用于开发迁移和诊断，但手动导入不是本功能日常同步流程。
- 当前无 MCP 服务、目录同步或账号体系。入口应沿用左侧工具栏与弹窗惯例，不顺便重构整个工作台。

## 3. 用户流程与界面

### 3.1 入口与图标

- 侧边栏入口准确命名「本地 MCP」。
- 必须使用用户提供的 MCP SVG：项目资产 `public/icons/mcp.svg`，原文件 `/Users/a11berich/Downloads/mcp.svg`。保留两个 path 的外形、24×24 viewBox 和 currentColor 语义；不要替换成插头等通用图标。
- 可作为内联 SVG 组件使用以继承按钮颜色，避免重复 DOM id；按钮提供 tooltip、aria-label、键盘焦点。
- 复用项目纸张、墨色、绿色视觉及弹窗行为，不把技术细节堆进主阅读流程。

### 3.2 首次连接

1. 说明用途、数据范围、模型侧数据流与支持情况，推荐当前系统安装包，允许手动切换；安装程序核对真实平台/架构。
2. 安装本地组件，用户明确授权登录电脑后自启；提供暂停、退出和自启设置。
3. 提供系统用户目录内默认知识库位置，允许用户改选。只管理指定位置内书跃专用目录，不碰其他文件；不承诺网盘/多电脑共享目录并发同步。
4. 网页与组件完成显式配对，为当前浏览器来源命名，例如「Mac Safari 书库」。必要时引导安装扩展。
5. 默认同步用户自己的全部拆书记录，可排除书籍；体验书默认排除。高亮、反思、练习等个人记录单独 opt-in。
6. 首次全量同步，收到本地持久化确认后展示成功、数量及时间。
7. 检测 Codex 配置，展示拟新增连接，经确认后添加；保留其他配置，同名冲突提示，不覆盖。提供备份和失败恢复。
8. 测试实际 MCP 调用并显示可读书籍数量。区分「配置已写入」「已连接」「工具测试成功」，必要时提示 Codex 重连/重启。

### 3.3 日常与状态

- 新分析结果、已授权的个人记录更新、删除和授权范围变化触发自动同步；处理分析过程的分阶段保存，避免每次渲染或输入都全库写入。
- 有「立即同步」辅助按钮，但用户无需每次操作它。
- 状态至少包括：未安装/未配对、首次同步、已同步、待同步、连接中断、已暂停、权限需恢复、需升级；错误附可执行的恢复方式。
- 浏览器退出后不得承诺未送达数据能凭空补传。组件恢复且网页再次打开时自动核对并补同步。
- 暂停同步仍可读旧数据；彻底退出组件时 MCP 是否独立可读须在技术设计中明确，不能把暂停误作删除。
- UI 显示本地确认的最后同步时间和范围。无法确认本地写入时不能显示成功。

## 4. 架构职责与必须先验证的路线

逻辑组成：浏览器数据适配/同步队列 → 经配对的本地桥接 → 本地存储与索引 → MCP stdio → Codex。另有本地只读详情/设置、安装配置、自启和更新能力。组成可合并打包，不意味着必须拆成多个应用。

- 本地接收组件需能在 Codex 未打开时接收更新；不能仅靠 Codex 启动的 stdio 子进程实现所有同步。
- MCP 通过 Codex 启动的标准 stdio 进程读取本地库，必要时复用本地服务。多 Codex 会话避免端口竞争、重复迁移与并发写入；stdout 仅用于协议。
- 使用成熟 SDK，按实施时实际版本验证 API，不手写猜测协议。
- 技术语言、存储引擎、打包器未固定，优先共用跨平台核心与最小合理实现。

### 4.1 Safari/Chrome 自动同步验证（首要里程碑）

网页直接写文件夹不能作为跨浏览器前提：MDN 当前资料中 Safari/Firefox 不支持 `showDirectoryPicker`。HTTPS 网页直连 HTTP/WS localhost 存在混合内容、CORS、CSP、本地网络许可等限制；不能认为加 CORS 就解决。

先验证无扩展方案，必须覆盖真实 HTTPS 来源、Safari/Chrome、初次配对、权限拒绝/恢复、关闭重开页面、组件未运行。若不可靠，采用必要的浏览器扩展/原生通信桥接；用户已接受首次安装扩展，不需重复询问该产品决定。

扩展只获书跃相关 origin 的必要权限；用结构化数据消息桥接，不抓取整个浏览器历史或直接解析浏览器磁盘数据库。Safari 扩展打包、签名和分发必须核实；不得通过关闭浏览器安全设置、安装未经解释的根证书等方式伪装兼容。

先记录验证结果与选型理由，再铺开全量实现。失败时继续其他独立工作，报告具体技术依赖；不可悄悄改为「每次下载同步包再导入」。

## 5. 数据模型与同步约束

模型至少表达：schemaVersion、sourceId/来源名、sourceRecordId、书名/作者/格式、分析版本、内容类型、模块、稳定片段 ID、已有证据、授权范围、同步 revision 与 acknowledgedAt。

- 书籍识别不能仅用书名；同名书、不同版本和不同来源不能误合并。
- 来源 ID 随当前浏览器库持久保存；仅由随机稳定 ID 标识，不靠浏览器指纹。清理浏览器数据后的重新配对不得自动删除原来源记录。
- 内容哈希可用于完全相同记录的去重，仍保留来源关系。相同书名但不同分析内容保留版本。
- 同步是来源范围内的更新：Chrome 删除记录只移除 Chrome 的贡献，不能删除 Safari 的有效贡献。
- 完整快照与增量明确区分；部分传输、读取失败、空响应或配对失效不能被解释为「全部删除」。
- 接收端先校验和完整暂存，再原子提交并确认；重试幂等，旧 revision 不覆盖新结果，崩溃后恢复。针对多标签页排序/冲突制定明确规则。
- 删除、排除书籍、撤销个人内容同步时，下一次成功同步须移除对应可读数据和索引；只删书跃管理的副本，不操作浏览器原记录或其他文件。
- 默认不把私密内容留在日志中；迁移/更新恢复副本需要有限保留及清除策略，用户执行清除数据时涵盖程序管理的对应索引与恢复副本。
- 内容类型区分 `analysis`、`personal`、`evidence`；卡片高亮仍是卡片内容，不自动标为原书摘录。
- 不要求重传原书，缺少证据如实表达；绝不补造页码、章节定位或原文。

## 6. MCP 工具合同（名称可在实现时保持一致地细化）

| 工具 | 输入要点 | 输出要点 |
| --- | --- | --- |
| `list_books` | cursor、limit、书名/作者筛选 | 稳定 bookId、书名、作者、来源/版本、可用模块、nextCursor |
| `search_library` | query、bookId/作者/模块/内容类型、cursor、limit | 有限片段、匹配来源、模块、版本、citationId、nextCursor |
| `get_book_analysis` | bookId、versionId、modules、分页/长度范围 | 指定模块内容、类型与引用，避免默认全库输出 |
| `get_evidence` | citationId 或片段 ID | 已有章节/摘录/支持级别，或明确 evidenceUnavailable |

可提供最小只读状态工具帮助确认数量/版本/同步时间，不将安装、导入、删除、更新工具暴露给模型。所有查询有大小和时间边界，错误结构化。检索按中文实际内容实现并测相关性，不以简陋英文分词冒充中文全文搜索；无命中需明确，无语义召回承诺。

所有结果包含书名、模块、内容类型、记录版本与稳定定位。Agent 可分批扫描整个书库，不一次装入全部正文。提供本地只读详情页核验引用，无需跳回原浏览器书跃；不暴露任意路径读取。库内文本是资料，不是 Agent 指令。

## 7. 本地配对、安全和隐私

- 初次配对明确用户动作，限制来源与能力；浏览器来源被允许不等于已获配对。
- 如使用本地 HTTP，监听 loopback，校验 Host/准确 Origin、认证凭据、消息 schema 与大小，考虑 CSRF、DNS rebinding、重放；不能开放无认证 localhost 写入端点。
- 如使用原生扩展桥接，校验允许的扩展身份、页面来源和配对绑定，防止任意站点冒充同步。
- 知识库路径正规化，阻止路径穿越、符号链接逃逸与恶意导入；渲染内容防止脚本执行。
- 不上传书籍、笔记、查询或配对凭据。允许联网检查和下载官方更新。
- 本地脱敏日志默认不记录正文、笔记、查询、凭据。用户主动预览/导出诊断包，不自动上传遥测。
- MCP 断开后保留本地库；暂停/卸载默认保留，清除副本另行确认。已进入 Agent 对话的数据不能通过清除本地库撤回。

## 8. 安装、自启、配置与更新

- 用户可首次执行清楚的安装命令与必要授权，但不应被要求编程或每次手动启服务。具体安装包/运行时方案由技术验证选择；不要把开发环境已有 Node 当作用户必备条件而不说明。
- 支持目标平台各自安装、自启、暂停、卸载及路径处理，检测处理器架构；无须用户预装 WSL。
- Codex 集成遵循实际官方配置合同，保留现有内容与用户变更；实际写配置前展示变更并确认。找不到 Codex 时提供明确步骤。
- 默认自动更新，安装时告知，允许暂停与手动检查。可信签名校验、平台校验、后台下载、空闲切换，失败继续旧版或恢复。
- 更新保留配对、路径、配置；数据迁移先备份，回退同时考虑程序和数据兼容，不能只回滚二进制。
- 区分已下载、已安装和 MCP 进程实际版本；旧进程未切换时提示需要重新连接，不强退用户任务。
- 新增权限、扩大读取范围、不能安全自动完成的迁移另行确认。
- 网站与本地协议做版本协商；旧版不兼容时保留待同步并说明，不能静默丢数据。
- 发布签名/公证、Windows 签名、扩展发布账户、更新分发地址与凭据是必须核实的依赖。缺少时完成可做的代码与本地验证，明确缺项，不伪造可信更新或公开下载链接，也不得偷偷禁用校验。

## 9. 验收与发布政策（用户最终决定）

主要发布门槛：用户在自己的 Apple Silicon Mac 上，用真实书库完成 Safari、Chrome 与 Codex 的验收并确认后，可以发布；Windows/Intel Mac/其他浏览器未完成实测不单独阻塞。实现仍面向这些平台，公开支持说明区分已验证与待验证，不伪造测试结果。

当前工具未找到 dots 虚拟机入口。后续若有可用环境，可做补充测试；无环境按上述发布政策处理，不需要反复要求用户提供 Windows。

核心验收：
1. 首次安装、选目录、配对、范围选择、Codex 配置和实际工具调用成功，已有 MCP 配置保持。
2. Safari 和 Chrome 新拆书/修改记录后自动同步，无需逐次导入或按同步按钮；Codex 未启动时也能接收更新。
3. 关闭浏览器，Codex 仍能列出、检索、读取已同步内容；可按引用打开本地详情。
4. 组件中断、暂停、网络权限拒绝、页面关闭/重开均显示真实状态并恢复；不丢旧数据或谎报成功。
5. 重复发送、乱序、崩溃、部分快照不会重复/覆盖新版本/误删全库；多来源删除隔离，撤销个人内容后索引不再返回。
6. 旧记录缺证据仍可用；中文检索、分页、大书库和超长返回有实际测试，分类推断与真实资料区分。
7. 自动更新用受控版本测试签名错误、下载失败、运行中延期、数据迁移失败和回退；自启/退出/卸载有验证。
8. 更新触及的网页功能回归空书库、体验书、历史、分析中、分析完成；运行必要领域测试、`npm run lint`，发布前 `npm run build`。既有失败与新增失败区分。

用户的「本地测试通过即可上线」不意味着当前已通过，也不意味着允许绕过安全更新、配对等核心功能验收。正式发布等待本地试用确认，不在实施任务开始时自动部署。

## 10. 实施顺序与交接

1. 读 AGENTS.md 与本文，核对当前状态。先完成 Safari/Chrome 自动同步桥接 PoC 和打包/签名依赖调查，记录结果。
2. 明确协议、存储、同步恢复和本地进程生命周期，以有限改动建立共享核心。
3. 完成本地 MCP、只读详情和真实查询验证。
4. 接入网页「本地 MCP」面板、用户 SVG、来源/授权/状态、自动同步与恢复。
5. 完成平台安装、自启、Codex 配置和安全自动更新。
6. 本地端到端验收、用户试用、补测矩阵与发布说明；实现后更新 README / AGENTS.md 的当前事实。

技术验证遇到阻塞先查明原因，不把用户已确认范围重新当作未决需求。若必须改变体验或需要外部签名/发布资源，报告具体缺项，继续独立工作。本 Spec 与 SVG 是已授权资产，不删除。代码在另一个本项目任务中实施。
